# Prepare a target without specializing the role

Load only the target profile explicitly supplied by the user, plus the target's applicable guidance. A target profile is configuration and a recipe, not a new role, independent authority or proof of current state. Keep credentials in an approved external handoff; neither profile nor captured outputs contain their values.

Before product execution, retain a run brief with source baseline, observed runtime origins/builds, actor roles, synthetic fixture ownership, permitted effects, explicit exclusions, provider/data prerequisites, evidence observers, cleanup and user/host limits. A missing total deadline or cost cap means none; do not invent one. Resolve the source/runtime distinction before substituting environments.

Use `audit.py init --target-profile <file>` when a profile is supplied. The manifest fingerprints its logical path, resolved path and bytes. Revalidate after a profile change and use a new evidence run when captured assumptions change. The helper checks freshness, not whether the profile's assertions are true.

Discover coverage through source and requirements across feature behavior, architecture/contracts, privacy/authorization, data/recovery, integrations, configuration/build/CI/deployment and observability. For each required claim record prerequisites, scenario, expected assertion, authoritative observer, failure/false-pass risks, cleanup and invalidation. The target profile need not enumerate all scenarios. Add newly discovered gaps rather than narrowing the user's purpose.

Prepare independent lanes:

- Normal product UI/API tests use designated synthetic actors and disposable/reversible records on the requested environment.
- Failure injection, schema/migration/rollback and interrupted replacement experiments use owned disposable dependencies from the same source baseline. They do not intentionally disrupt shared services. Record the limited transfer of their results to the deployed target.
- Infrastructure repair and product fixes remain outside testing-only authority. Identify the missing prerequisite and request an unblock while independent work continues.

Use a blocker queue containing claim IDs, observed failure, missing input, requested action and work that can continue. Ask in the current chat; no external notifications unless directly requested. Checkpoints preserve outstanding obligations and uncertain writes. Do not report completion because a context window or command ended.

## Current ledger and cleanup

The current matrix and diagnostic report summarize linked detailed artifacts. Retain historical attempts separately. Before declaring coverage complete, reconcile all material source risks, outcomes, review dispositions, blocked/unrun checks, accepted exceptions and fixture dispositions. Hash validation does not replace this review.

Record each fixture's ID, purpose, owner, initial state if edited, intended disposition, actual state and exact recovery/cleanup route. Restore existing shared state. Retain sanitized evidence. Approved minimal retention for defect review is accounted for; unapproved retention stays unresolved. Follow actual deletion gates and stop only owned temporary resources.

See the package `templates/target-profile.md` and `templates/run-ledger.json` for blank inputs. Do not copy target-specific content back into this skill.
