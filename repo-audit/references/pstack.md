# Integrate installed workflows

Resolve resources from the current skill catalog or supported installed-plugin discovery. Never hardcode a plugin cache version into the reusable package. Record absolute resolved paths and hashes in the run. Missing required resources block a claim of Pstack-compliant execution. They do not block a useful partial baseline assessment.

Run `python3 <skill-root>/scripts/audit.py doctor --pstack-root <plugin-root> --evidence-first <skill-path> --verify-pr <skill-path> --out <run>/dependencies.json`. The last two arguments refer to actual resolved skill files when installed. Evidence-First is required for the full evidence workflow. `verify-pr` is required only when a PR-specific review is requested. The doctor checks files, not whether an agent read or obeyed them. Record missing optional resources in the assessment.

Load `poteto-mode/SKILL.md`, its runtime contract, portable agent prompt, and matched playbook before work. Read the leaf for each applied principle. Keep the playbook's named steps and explicit skip explanations. Invocation of this audit skill is not a trusted sticky receipt. The installed derivative's hook may target only `pstack-poteto-agent`. A new profile does not inherit hook state by name similarity. Initialize explicitly and report current-turn-only operation when persistence is unverified. Do not modify Pstack hooks or impersonate a profile to bypass this limit.

Use these owners rather than copying their procedures:

| Need | Owner and boundary |
| --- | --- |
| Evidence quality | Evidence-First Skill. Source authority, history, counterevidence, claim ledger, privacy, and research handoff. |
| Baseline and flow trace | Investigation playbook and `how`. Use `why` when historical motivation affects the question. |
| Runtime symptom diagnosis | Runtime forensics. Captured profiling artifacts use Trace forensics. Neither authorizes a product fix. |
| Independent coverage | `swarm`. Bound slices and isolate runtime state. Respect observable capacity and the declared fallback. |
| Review of implementation changes | `interrogate`, with its actual review scope. It does not replace the whole-repository assessment. |
| Actual PR review | `verify-pr`, retaining exact revisions, independent context, publication boundaries, and project gates. |
| Verification-tool construction | Feature or Bug fix as appropriate, only for authorized tooling changes. Follow architecture and behavior-test requirements. |
| Missing repository-local control skill | `create-verification-skill`. Inspect the repo, generate a real launch/doctor/drive/evidence/cleanup recipe and feature map, then execute it before delivery. See project-verification.md. |
| Existing verification skill and map upkeep | `maintain-verification-skill`. Preserve its source and live coverage requirements. A sampled audit cannot claim its all-feature clean outcome. |
| Agent behavioral evaluation | Eval playbook, with organic tasks, hidden acceptance answers, fresh contexts, independent graders, and inspected outputs. |
| Continuation | Session pickup and Pause safely when applicable, preserving the audit's authority and evidence freshness. |

For a full audit that spans assessment and authorized verification setup, the overall audit contract remains the domain specification. Use Pstack's `figure-it-out` when no bundled playbook covers the run. It may compose the phases but cannot erase contract obligations or add authority. Do not route every audit into shipping, orchestrate, an autonomous loop, or a new goal.

Fresh independent review workers receive standalone requirements, exact revisions, scope, guidance, and raw safe artifacts. Omit author self-assessment and earlier verdicts. Use supported fresh-context delegation. If unavailable, report the independence gap. Another persona in the same context is not independent review. Model diversity must be observed, not inferred from role labels.

Preserve original worker receipts. `swarm` uses PASS, ISSUES, and BLOCKED. Map ISSUES to FAIL only where evidence proves a particular claim is false. Unknown or missing evidence stays INCONCLUSIVE or BLOCKED. Keep findings distinct from missing proof and suggestions.

The parent retains integration, protected operations, external writes, and final verdict authority. A worker summary is a lead, not completion evidence. Inspect artifacts and rerun only when freshness, coverage, or the selected workflow requires it.

Apply the common contract's delegation boundaries and delegation.md before invoking `swarm`. Keep Pstack's frame, fan-out, aggregate and report phases. Do not substitute an audit-specific orchestration engine. Read-only discovery, runtime execution and independent challenge are different assignments with the same evidence and authority rules. Parallel discovery does not imply parallel product driving or independent verification.
